## Scene fixture schema (vh.scene/1, observed in 2 of his 30 files; keys and types only)

Top level: `schema` ("vh.scene/1"), `name`, `captured` (UTC), `build` (version + commit), `bug` and `source` (hand-written: what failed, captured vs built from event rows), `center` [x,y,z], `radius`, `player` {feet, eye, camera, forward, yaw, maxPlace, flags gui/guiContainer/station/ship/attached/inBed}, `objects[]`, `terrain` {x0, z0, step, nx, nz, h[] row-major heights}, `fight.seen[]`, `zdoSession`, `deadZdos[]`, `ledger` {schema, next, entries, groups}. A scene may also carry `after.objects[]` (a before/after pair: a picked bush).
Object: `id` ("session:uid", valid for one load), `inst` (instance id), `prefab`, `pos`, `yaw`, `rot` (quaternion), `parts[]` (component names), `childParts[]`, `ghost`, `kind` (piece | destructible | item | pickable | rock), optional blocks `piece` {name, category, walk (rug/stair/...), health, support, maxSupport}, `pickable` {picked}, `door` {state}, `fire` {fuel/burning}, `container`, `cooking`, `itemStand`, `item`, `breakable`/`pickaxeOnly`, and `colliders[]` {layer, trigger, mesh, convex, interact (on the player's interact mask), c (centre), h (half extents), q (quaternion), burn/active for a fire's burning area}. A non-convex mesh is stored as its oriented bounds.
Sizes: 1 KB (one bush) to 783 KB (1280 objects, 1914 colliders); all 30 together 5.6 MB. Names are `<place>-<what>-<date>.scene.json`.
Walk list schema (vh.walks/1): `{doc, from[x,y,z], scenes[files, newest first, the first wins an object two scenes hold], walks[{name, to, note, run?, face?, arrive?}]}`; 19 walks in spawn-base.json; other lists: steep.json (run-ups), stalls-*.json, vhtest-*.json.
Other fixtures: `events/*.jsonl` (a real bench's event rows to test the trace reader), `decide/*.json` + `*.holdout.json` (judge cases), `social/lines.json` (chat cases with `want`), `cli/argecho.ps1` (CLI option binding).

## How he tests without the game

- mcpcheck loads the built DLLs outside the game with the game's assemblies resolved from the install folder, calls the tool registry through JSON-RPC, and runs `[Golden("section")]` methods found by reflection: pure rule classes on canned data and on scenes. It needs the game's DLLs, as ours does.
- Live adapters are split into a thin engine read that fills a plain record and a pure core; scenes feed the cores. Wiring that needs a Player is asserted by grep gates (a call is present, a banned call is absent).
- Gates are per area, dot-sourced at the end of the area's section; he moved owner bans from regex tables to attributes checked over the IL (Cecil). Gate files: act, actor, cli, companion, dead, design, docs, errors, fight, neighbours, owners, resources, runtime, stands, survival, terrain, threads, travel, voyage, workbench, world.
- Nothing blocks a commit automatically: there is no hook and no CI. "Gate" means the full `vh check` before a merge and `vh live accept`/`acts` as the merge gate for changes under Actor/ and Live/, run by hand. Same as our AGENTS.md rule.

## Contradicts or bugs

- None of his game facts in this module contradicted what I know. Not verifiable here (his own live measurements): the 38 degree slide limit, run-up to 57.5 degrees, jump apex values, `AddNoise(50)` on the hammer's remove click. Confidence in "wood_window has a Door component and shows up as a door": medium-high (his live log shows 12 toggles of one on a 2.7 m walk; I did not check the decompile).
- Our own `Walk.Check` (ext/ClientTools.cs): ignores triggers (`QueryTriggerInteraction.Ignore`), so a path through a portal or lit fire is reported ok; `FirstBlocker` skips every collider under a `Door`, so windows and locked or warded doors are passable and an open leaf in the way is not seen; `GroundHit` excludes doors, so a lowered drawbridge deck is "no ground". Confidence high (read the code); how the game treats each is from his notes.
- errors.ps1: skips a catch when `//` appears earlier on its line (a URL string before a catch hides it), and tests "inside a string" by counting quotes (wrong for verbatim and interpolated strings); `catch (SomeTypedException e) { return; }` is never flagged. Minor, by design.
- accept.ps1 / mcpcheck: several assertions can never fail on an empty world (see idea 22). Gate files hard-code `F:\SteamLibrary\...` (dead, owners, threads) and docs.ps1 a `C:\Users\reapz\Documents\vh\decomp` fallback: same class as the paths already noted in the review.
- fight/runtime/neighbours gates pin source statements by regex (for example exact `Time.time + ...` shapes); he removed several for that reason in a later audit but kept many. Brittle, not wrong.
- `Child` in accept.ps1 judges a sub-script by `$LASTEXITCODE` after piping its output; a script that ends without `exit` returns 0 even after a failed Check. His scripts all end with `exit $fail`, so it holds today.
