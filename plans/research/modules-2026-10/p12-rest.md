## Contradicts or bugs

- Fire clearance of 1 m (his "R3", and ours in `plan_check` `fire-clearance`) is not a placement rule I know of. The real failure is smoke blocked for 4 s (fire goes out). A metre of air is a proxy; replace or back it with the smoke test (#3). Confidence: medium (I know of no Fireplace clearance check in Player placement; not decompiled here).
- `Teleportable` treats any item with m_toolTier >= 1000 as always blocking a portal. I do not recognise this rule in vanilla Inventory.IsTeleportable (m_teleportable only). It may be new in 1.0.x. Confidence: low; check on our install before copying anything like it.
- `Readers.StabilityScan` uses a fixed threshold of 20 for "will degrade/collapse". The game uses a per-material minimum (WearNTear.GetMinSupport), which our `stability_scan` already does. His number is wrong for wood. Confidence: high.
- `Views.Survey` `levelable` = height range <= 2 x hoe clamp and water < 5 percent is a heuristic, not a game rule. Confidence: high that it is only a heuristic.
- `Fires` reader (his and ours) computes seconds left as fuel * m_secPerFuel; correct for plain fireplaces, but infinite-fuel fires and fires with a roof/rain/water-exposure check (`m_blocked`, wet fires) are not covered. Confidence: medium.
- Portals: `Rules.BossActive` treats global key `activeBosses` > 0 as a running boss fight; I could not confirm that key and the NoBossPortals semantics (key is set while a boss is alive in some versions). Confidence: low.
- Ship drafts for Longship (0.9) and Drakkar (1.3) are labelled estimates in his own table; only Karve (0.5) was measured. Do not use them as facts.
- His smoke wiki table says several sources spawn every 0.5 s, but his own derived real interval is 1.5-2 s (the spawner waits until the last smoke clears the test sphere). Consistent with the code comment, but check the value of `Smoke.m_force` and rise on our install before trusting his derived `ClearTime`.
